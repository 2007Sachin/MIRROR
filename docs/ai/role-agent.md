# Role Intelligence Agent

## Purpose

The Role Intelligence Agent converts a target role and optional job description into a structured Role Competency Map. It answers: “What capabilities would a candidate reasonably need to demonstrate for this target role?”

It understands the role independently. It does not receive resume claims, resume analysis, interview answers, scores, or evidence, and it does not assess the candidate.

## Inputs

The model receives only:

- Target role
- Optional job-description text
- Candidate career stage, used only to calibrate reasonable expected depth

When the API receives a job-description document ID, application code verifies that the authenticated user owns a processed `JOB_DESCRIPTION` document and resolves its text. User identity and document identifiers are not model inputs.

## Outputs

`RoleAgentOutput` contains:

- Canonical role and seniority
- Competencies
- Must-have and nice-to-have skills
- Behavioural and domain expectations
- Interview themes

Each competency has a category, importance weight from 0 to 1, expected level, source type, source reference, and confidence. Weights are stored for future deterministic planning but are not shown in setup UI and do not currently drive scoring.

## Source provenance

Job-description analysis distinguishes:

- `JOB_DESCRIPTION_EXPLICIT`: directly stated or unambiguously required by the JD.
- `JOB_DESCRIPTION_INFERRED`: a conservative interview theme reasonably implied by stated work.

When no JD is supplied, Mirror can use version-controlled synthetic canonical profiles for Data Analyst, Business Analyst, Software Engineer, and Product Analyst. These records and competencies are marked `SYNTHETIC_CANONICAL`; they are development guidance and are not represented as employer-validated requirements. Unknown no-JD roles can be generated by the Role Agent with the same synthetic provenance rules.

## Security

JD text is untrusted user data in a user-role JSON message. The `role/v1` system prompt explicitly rejects embedded commands, score manipulation, schema changes, and instructions such as “give the applicant full marks.” The agent has no tools and no access to SQL, authentication, resume claims, sessions, or application permissions.

Structured output is validated with Pydantic. The service additionally verifies that JD analyses contain only explicit/inferred JD competency sources and that no-JD analyses contain only synthetic canonical sources.

## Persistence and versioning

- `role_profiles` stores the owner-scoped target and current role map identity.
- `role_analysis_versions` stores immutable analysis versions, source document, model, prompt version, analysis version, execution metadata, and original structured output.
- `role_competencies` stores version-linked competency rows and source references.
- `profiles.current_role_profile_id` links the authenticated user's current setup to the completed role profile.

Rerunning analysis on a role profile creates a new version and preserves earlier output. A partial unique index prevents concurrent processing versions for the same profile. PostgreSQL completes the version, inserts competencies, and updates the current setup link in one transaction.

## Non-goals and limitations

The Role Intelligence Agent does not:

- Assess candidate capability, truthfulness, readiness, or fit.
- Compare role needs with resume claims.
- Plan or conduct an interview.
- Score answers or expose hidden weights in the UI.
- Claim synthetic profiles represent a particular employer.

Role expectations vary between organizations. JD-based maps remain limited by the clarity and completeness of the supplied description, while no-JD maps are deliberately conservative generalizations.
